# Factual-state mechanism trial

14 September 2026. Experimental source only; not imported by the conversational runtime, knowledge ingestion or Slack adapter.

The preceding Qwen and gpt-oss oracle screens failed despite receiving correct short evidence. The first factual-state trial selected a passage with one model call, checked support with another, and rendered the accepted attributed quote deterministically. It preserved all eight unknowns and rejected all ten forged candidates, but missed one supported observation before the checker saw it. Its failed development verdict and source snapshots remain in evidence.

The single mechanism revision removes the selector. It enumerates whole eligible records, checks each against the question and complete source bundle using the unchanged checker prompt, and accepts exactly one supported record. Missing/invalid assessments or multiple accepted records yield unknown. This can conservatively reject complementary or duplicated evidence; it is a bounded experiment, not general multi-source synthesis. The checker receives no confidence score or development labels. Calls use the existing local Qwen endpoint; no model service is started or reconfigured.

The supported targets are completed actions, observations and decisions. Instructions may be identified but cannot satisfy a completed-action question. There is no open-domain question router, persistent fact store, archive importer, audience authorisation adapter, graph, or persona rewrite in this experiment. The supplied metadata is synthetic and trusted by the caller. Real source identity and audience enforcement must precede any real integration.

The decisive limitation is semantic: a false state label can still be admitted if the checker wrongly endorses it. The unit suite documents that counterexample explicitly. The revision requires an entire source record, so it cannot strip a denial or embedded speaker by selecting a substring, and offsets identify the whole record. Deciding whether that whole record supports the requested fact remains a model judgment. Supported attribution means source support for a reported statement, not verified external truth. No finite screen establishes zero population errors.

The first screen uses 16 paired development examples (eight affirmative and eight unknown) and ten forged schema-valid candidates. Two forged candidates strip a phrase from a denial or another speaker's quotation. Independent review corrected the status question to a historical check before the first generation. The automatic `stateMatches` field compares state labels only; every actual accepted quotation and final answer requires semantic review. A positive row with the wrong quotation is a failure even if its label matches. Always abstaining fails all eight affirmative examples.

Canonical deterministic verification remains `npm run verify`. The manual synthetic revision experiment is `node scripts/factual-state-trial.mjs`, run from this repository, using the frozen fixture and pinned prompts/settings. An independently written challenge set is selected by `--challenge` only after the development gate passes. Each run refuses to overwrite its receipt, admits at most 48 sequential inference calls within a 15-minute start budget, and bounds each call separately. Request failures are recorded as failed rows. Final model JSON is retained only for synthetic inputs; raw reasoning is not stored. No external Slack message is part of this probe.

Evidence and independent reviews are in the parent workspace's `evidence/` directory. The older 40 unseen oracle cases remain untouched. Passing this small structured-source trial would justify a fresh adversarial structured-source screen; it would not validate an archive parser or allow deployment. A failed checker requires an evidence-led mechanism revision, not bulk ingestion or a more agreeable model judge.

V2 result: v2 passed the 26 development cases under independent semantic review, then failed the independently authored 12-case challenge (four of six supported answers accepted, all six unknowns preserved). It lost direct negative evidence and James's explicit self-report beside a third-party quotation. No unsupported positive was found in those screened final outputs, but the agreed recall capability did not pass. Its challenge is now regression material. See `../evidence/factual-state-trial-results-20260914.md` from the repository root.

V3 separates answerability, subject attribution and polarity. It retains whole-record candidate binding and requires exactly one accepted record. Two independently reviewed gold changes recognise explicit non-decisions and withdrawals as direct answers, without claiming a provider was chosen. Under this revised contract the fixed development set contains 16 answerable cases, 12 ordinary unknowns and ten forged candidates. Nonthinking Qwen passed 37/38 under independent actual-output review: it missed an explicit non-decision. All accepted final quotations and polarities passed that review.

A six-case Qwen thinking smoke test passed only 5/6. It fixed the non-decision but wrongly credited an old decision record with the meaning of a later withdrawal. The exactly-one guard blocked that false attribution because the current withdrawal was also accepted. Do not loosen that guard or claim the checker itself has zero false positives. The larger fixed-contract comparison uses `--gpt` against a separately managed local GPT-OSS 120B trial, native medium reasoning, and a verified Harmony template. Model lifecycle is outside this harness. A single bounded 38-case comparison is justified; its fresh independently authored 12-case challenge stays reserved unless development passes strict semantic review. No private archive records are used in these model screens.

The separate archive delivery repair reconstructs all indexed parts of each normalised source record and transports evidence as complete JSON, omitting whole records when a result exceeds its budget. This fixes demonstrable truncation in retrieval and tool delivery. It does not establish semantic accuracy, original speaker identity or completeness of an original conversation. Keep the factual-state prototype disconnected until its acceptance criteria pass.

V4 corrects an omitted input premise: questions now require an explicit trusted requester of James, and source/question pronouns are distinguished. There is no default or inference of the requester's identity. This supports the owner-only experimental scope; a future runtime adapter must derive it from authenticated authority. All 38 prior question/source texts and gold labels are unchanged. Both corrected-input runs failed: Qwen 37/38 with a missing-update-to-negative false acceptance; GPT 35/38 with instruction-to-completed-use false acceptance and a temporal abstention. See `../evidence/answerability-trial-results-20260914.md`. Gemma's fixed comparison uses `--gemma`; every candidate must pass its native formatting and schema checks before semantic scoring. Current artifacts use the `owner-identity-` prefix; old source snapshots and results remain in evidence.
